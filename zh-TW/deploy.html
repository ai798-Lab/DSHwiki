02 / DEPLOY

部署上手

從零到跑起來，四步。全部指令都與官方 README 逐條核對過。
01

安裝 CLI

npx 一行指令直接跑，macOS / Linux / Windows 都行，Node 22.19+ 即可。
02

串接模型

填入 DeepSeek API key，或接 Ollama 直接用你本機跑的模型。
03

啟動

終端機裡直接開工；不愛看命令列，用 dsh web 啟動瀏覽器介面。
04

裝第一個外掛

從精選清單挑一個裝上——從這裡開始，一切皆外掛。

UPGRADE / UNINSTALL

note
README、apps/cli/README.md、docs 使用者指南均未提供升級/解除安裝指令（逐一核對為 ABSENT)；社群討論中出現過清 npx 快取的做法(rm -rf ~/.npm/_npx，見 #49/#897)，屬排除故障的手段，非官方升級流程

ISSUES

npx 無法安裝 | npm 也無法安裝 (#1772，已解答） ↗
原PO自答(2026-08-16):Debian 未裝 build-essential 導致 node-pty 原生模組編譯失敗；用 apt 安裝 build-essential 後安裝成功
在 ArchLinux 上無法安裝 (#49,18 則留言） ↗
高讚解法：① pacman -Syu base-devel 裝編譯工具；② 改用 Bun:bun add --global @deepseek-ai/dsh(node-pty 在 Bun 白名單內）;③ 堅持用 npm 就清快取後放行建置腳本：rm -rf ~/.npm/_npx && npx --allow-scripts=node-pty @deepseek-ai/dsh@0.1.0-rc.6 web；另一方案：npm config set allow-scripts=@deepseek-ai/dsh-subprocess-local,koffi,node-pty,@google/genai,protobufjs --location=user
命令列方式安裝不成功 (#897,10 則留言） ↗
社群診斷：系統預設的 g++ 9.4.0 不支援 -std=gnu++20（需 GCC 10+)；解法：先清 npx 快取，再 CC=gcc-11 CXX=g++-11 npm install -g @deepseek-ai/dsh，之後 dsh web
npm 全域安裝後 dsh web 啟動失敗：node-pty 原生模組 pty.node 缺失 (#1219) ↗
根本原因：node-pty v1.1.0 沒有 Linux x64 (Node 24/ABI 137) 的預編譯產物，npm 安裝腳本靜默失敗；手動繞過：進入 node-pty 目錄執行 npx node-gyp rebuild 產生缺少的 pty.node；貼文內無官方回覆(0 回覆）
dsh 安裝外掛時報錯 Ignored build scripts (#2230) ↗
未抓取到解法細節(1 則留言，未深入核對）；現象與 pnpm 預設忽略相依套件建置腳本的安全策略有關，可與 #49 的 allow-scripts 方案互相參照——此條解法待補
