02 / DEPLOY

導入ガイド

ゼロから動かすまで 4 ステップ。コマンドはすべて公式 README と逐一照合済み。
01

CLI をインストール

npx のワンコマンドでそのまま動く。macOS / Linux / Windows いずれも OK、Node 22.19+ があればいい。
02

モデルを接続

DeepSeek API key を入力するか、Ollama をつないでローカルで動かしているモデルをそのまま使う。
03

起動

ターミナルでそのまま作業開始。コマンドラインが苦手なら、dsh web でブラウザ画面を立ち上げられる。
04

最初のプラグインを入れる

厳選リストからひとつ選んで入れよう——ここから先は、すべてがプラグインだ。

UPGRADE / UNINSTALL

note
README、apps/cli/README.md、docs のユーザーガイドのいずれにもアップグレード/アンインストールのコマンドは記載されていない(1 件ずつ確認して ABSENT);コミュニティのディスカッションでは npx キャッシュを消す手法(rm -rf ~/.npm/_npx、#49/#897 参照)が出ているが、これはトラブルシューティングの手段であり公式のアップグレード手順ではない

ISSUES

npx でインストールできない | npm でもインストールできない (#1772,解決済み) ↗
投稿者による自己解決(2026-08-16):Debian に build-essential が入っておらず node-pty のネイティブモジュールのビルドに失敗していた;apt で build-essential を入れたところインストールに成功
ArchLinux でインストールできない (#49,コメント 18 件) ↗
支持の多い解法:① pacman -Syu base-devel でビルドツールを入れる;② Bun に切り替える:bun add --global @deepseek-ai/dsh(node-pty は Bun の許可リストに入っている);③ npm を使い続けるならキャッシュを消してビルドスクリプトを許可する:rm -rf ~/.npm/_npx && npx --allow-scripts=node-pty @deepseek-ai/dsh@0.1.0-rc.6 web;別案:npm config set allow-scripts=@deepseek-ai/dsh-subprocess-local,koffi,node-pty,@google/genai,protobufjs --location=user
コマンドラインでのインストールが成功しない (#897,コメント 10 件) ↗
コミュニティによる原因特定:システム標準の g++ 9.4.0 が -std=gnu++20 に非対応(GCC 10+ が必要);解法:まず npx キャッシュを消し、CC=gcc-11 CXX=g++-11 npm install -g @deepseek-ai/dsh を実行してから dsh web
npm でグローバルインストール後に dsh web が起動しない:node-pty のネイティブモジュール pty.node が欠落 (#1219) ↗
根本原因:node-pty v1.1.0 には Linux x64 (Node 24/ABI 137) 向けのビルド済み成果物がなく、npm のインストールスクリプトが黙って失敗していた;手動の回避策:node-pty ディレクトリに入って npx node-gyp rebuild を実行し、欠落している pty.node を生成する;スレッド内に公式の返信はなし(返信 0 件)
dsh でプラグインをインストールするとエラー Ignored build scripts が出る (#2230) ↗
解法の詳細は取得できていない(コメント 1 件、深く確認していない);現象は pnpm が既定で依存関係のビルドスクリプトを無視するセキュリティポリシーに関係しており、#49 の allow-scripts の案が参考になる——この項目の解法は追記待ち
