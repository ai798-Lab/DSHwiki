EverOS

ひとつの記憶を、どこでも。

ポータブルなメモリ層。ローカルファーストで Markdown ネイティブ、自己進化する記憶ひとつを複数の agent アプリで共有できる。
12,081 star v1.2.3 メモリ / ストレージ GitHub ↗

インストール

Python 3.12+、および OpenRouter API key が 1 つ。既知の落とし穴：ハイブリッド検索には embedding provider が必要で、最小構成のワンクリック設定では "method": "keyword" しか使えない。Office 文書の取り込みにはシステムへの LibreOffice インストールが必要。/api/v1 は互換用の旧別名で、将来削除される。オプション機能が欠けている場合、API は HTTP 422 を返す。v1.2.3 以降、バックグラウンドループが失敗するとプロセスが SIGTERM で終了するため、systemd/Docker/K8s などの外部再起動機構が必要。
Python パッケージ：pip か uv で入れて、付属のコマンドを実行します。
uv pip install everos # or: pip install everos
マルチモーダル（任意）
uv pip install 'everos[multimodal]' # or: pip install 'everos[multimodal]'

完全チュートリアル

01まず everos demo でデモを動かす（API key 不要）
02everos init で ~/.everos/everos.toml と ~/.everos/ome.toml を生成する
03OpenRouter API key を everos.toml に記入する
04everos server start でサービスを起動し、curl http://127.0.0.1:8000/health で確認する
05/api/v2/memory/add、/api/v2/memory/flush、/api/v2/memory/search でメモリの書き込み、永続化、検索を行う

config

# everos.toml [llm] model = "openai/gpt-4.1-mini" api_key = "<OPENROUTER_API_KEY>" base_url = "https://openrouter.ai/api/v1"

特徴

·Markdown のメモリファイル + Git によるバージョン管理、ローカルの SQLite + LanceDB インデックスで、外部データベースへの依存なし
·キーワード + ベクトルのハイブリッド検索。user/agent/app/project/session の多次元直交検索に対応
·セッション間のメモリのリフレクション（reflection）による自己進化。マルチモーダル取り込み（画像/PDF/音声/文書）はオプション。エコシステムには Claude Code プラグインや EverMem Sync などがある
