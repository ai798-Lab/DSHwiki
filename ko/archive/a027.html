Harness 对决：Claude Code vs OpenCode vs Pi——质量相同，路径悬殊

u/xquarx · 2026-07-26 · 283 · 进阶
竞品对比社区实测观点金句数据实证背景知识
원문 ↗
DSH 发布前两周的最佳社区实验：本地 vLLM 固定跑 V4 Flash，唯一变量是 harness，对比 Claude Code、OpenCode、Pi。反直觉结论：三者产出的代码 diff 基本相同，但 Claude Code 落地相同结果要花最快者近 4 倍时间，差异全在提示词和调用路径。对写文章的启发：「harness 本质是提示词包、不改质量只改效率」正是 DSH「一切可换」设计哲学的需求侧注脚。

핵심

·harness 不改变产出质量，只改变效率：三个 harness 生成相同 diff，路径和成本悬殊
·「harness 本质上就是一套提示词」——Claude Code 上下文膨胀严重，Pi 最干净且可整个换掉
·Claude Code 的闭源与膨胀两大吐槽，正是 DSH「开源+极简内核+插件化」的对位卖点

핵심 수치

·本地 vLLM 约 180 tok/s 跑 V4 Flash（控制变量）
·Claude Code 落地相同 diff 花最快者近 4 倍时间
·关掉 reasoning 可省 75% token（生成 2k 而非 8k）
·283 赞 / 140 评论的高热对比帖

인용할 문장

质量没变，三个 harness 生成了相同的代码 diff，但路径截然不同……「Pi 靠推理，OpenCode 靠委派」，而 Claude Code 太爱探索代码库了，可能爱过头了。
楼主核心结论，反直觉且有画面感，适合做「harness 到底改变什么」段的定调引语
harness 实际上就是一套提供给模型的提示词。Claude Code 上下文里塞了一大堆『模型应该如何行动』的自定义指令，不是秘密。OpenCode 膨胀得少、还能继续精简。Pi 是三者里最干净的，而且可以整个换掉。
37 赞最高赞，一句话捅破 harness 的本质，是解释 DSH「万物皆插件」价值的最强社区证据
很多日常任务可以关掉 reasoning 跑，token 能省到 1/4（生成 2k 而不是 8k），速度和上下文长度都受益。
可直接迁移成 DSH 省钱技巧条目：日常任务关推理，省 75% token
他们确实砍了系统提示词，但那不是 harness 里最大的负担，大头是其他那些定义——砍的是 15-20% 里的 80%。
对「精简提示词」营销话术的清醒拆解，写对比段时防止把优化说得太简单
但它是闭源的。
针对 Claude Code 的三字暴击（10 赞），引出「社区为什么需要开源 harness」，为 DSH 的 MIT 开源做铺垫
