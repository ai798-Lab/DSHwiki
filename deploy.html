02 / DEPLOY

部署上手

从零到跑起来，四步。全部命令与官方 README 逐条核对。
01

安装 CLI

npx 一条命令直接跑，macOS / Linux / Windows 都行，Node 22.19+ 即可。
02

接入模型

填 DeepSeek API key,或者接 Ollama 直接用你本地跑的模型。
03

启动

终端里直接开工；不爱看命令行，dsh web 启动浏览器界面。
04

装第一个插件

从精选清单挑一个装上——从这里开始，一切皆插件。

UPGRADE / UNINSTALL

note
README、apps/cli/README.md、docs 用户指南均未提供升级/卸载命令（逐一核对为 ABSENT);社区讨论中出现过清 npx 缓存的做法(rm -rf ~/.npm/_npx,见 #49/#897),属排障手段非官方升级流程

ISSUES

npx 无法安装 | npm 也无法安装 (#1772,已解答） ↗
楼主自答(2026-08-16):Debian 未装 build-essential 导致 node-pty 原生模块编译失败；apt 安装 build-essential 后安装成功
在ArchLinux上无法安装 (#49,18 评论） ↗
高赞解法：① pacman -Syu base-devel 装编译工具；② 改用 Bun:bun add --global @deepseek-ai/dsh(node-pty 在 Bun 白名单内）;③ 坚持 npm 则清缓存后放行构建脚本：rm -rf ~/.npm/_npx && npx --allow-scripts=node-pty @deepseek-ai/dsh@0.1.0-rc.6 web;另一方案：npm config set allow-scripts=@deepseek-ai/dsh-subprocess-local,koffi,node-pty,@google/genai,protobufjs --location=user
命令行方式安装不成功 (#897,10 评论） ↗
社区诊断：系统默认 g++ 9.4.0 不支持 -std=gnu++20（需 GCC 10+);解法：先清 npx 缓存，再 CC=gcc-11 CXX=g++-11 npm install -g @deepseek-ai/dsh 后 dsh web
npm 全局安装后 dsh web 启动失败：node-pty 原生模块 pty.node 缺失 (#1219) ↗
根因：node-pty v1.1.0 无 Linux x64 (Node 24/ABI 137) 预编译产物，npm 安装脚本静默失败；手工绕过：进入 node-pty 目录执行 npx node-gyp rebuild 生成缺失的 pty.node;帖内无官方回复(0 回复）
dsh安装插件时报错 Ignored build scripts (#2230) ↗
未抓取到解法详情(1 评论，未深入核对）;现象与 pnpm 默认忽略依赖构建脚本的安全策略相关，可与 #49 的 allow-scripts 方案互参——此条解法待补
