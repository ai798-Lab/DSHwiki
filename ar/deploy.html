DEPLOY

التثبيت والانطلاق

من الصفر إلى التشغيل في أربع خطوات. جميع الأوامر مطابَقة بندًا ببند مع README الرسمي.
01

تثبيت CLI

أمر npx واحد يشغّله مباشرة على macOS وLinux وWindows، ويكفي Node 22.19+.
02

ربط النموذج

أدخل مفتاح DeepSeek API، أو اربطه بـ Ollama لتستخدم النموذج الذي تشغّله محليًا.
03

التشغيل

ابدأ العمل من الطرفية مباشرة؛ وإن لم تكن من محبي سطر الأوامر، فالأمر dsh web يفتح واجهة المتصفح.
04

تثبيت أول إضافة

اختر إضافة من القائمة المختارة وثبّتها — من هنا تبدأ، فكل شيء إضافة.

UPGRADE / UNINSTALL

note
لا يقدّم README ولا apps/cli/README.md ولا دليل المستخدم في docs أي أمر للترقية أو إزالة التثبيت (تم التحقق منها واحدًا واحدًا والنتيجة ABSENT)؛ وظهرت في نقاشات المجتمع طريقة مسح ذاكرة npx المؤقتة ‏(rm -rf ~/.npm/_npx، انظر #49/#897)، وهي وسيلة لحلّ المشكلات لا إجراء ترقية رسمي

ISSUES

تعذّر التثبيت عبر npx | وتعذّر عبر npm أيضًا ‏(#1772، تمّت الإجابة)
أجاب صاحب المنشور بنفسه (2026-08-16): عدم تثبيت build-essential على Debian تسبّب بفشل بناء وحدة node-pty الأصلية؛ وبعد تثبيته عبر apt نجح التثبيت
تعذّر التثبيت على ArchLinux ‏(#49، 18 تعليقًا)
الحل الأعلى تأييدًا: ① pacman -Syu base-devel لتثبيت أدوات البناء؛ ② أو التحوّل إلى Bun: ‏bun add --global @deepseek-ai/dsh (فـ node-pty ضمن قائمة Bun المسموح بها)؛ ③ أو الإصرار على npm مع مسح الذاكرة المؤقتة والسماح بسكربتات البناء: ‏rm -rf ~/.npm/_npx && npx --allow-scripts=node-pty @deepseek-ai/dsh@0.1.0-rc.6 web؛ وحل آخر: npm config set allow-scripts=@deepseek-ai/dsh-subprocess-local,koffi,node-pty,@google/genai,protobufjs --location=user
التثبيت من سطر الأوامر لا ينجح ‏(#897، 10 تعليقات)
تشخيص المجتمع: إصدار g++ 9.4.0 الافتراضي في النظام لا يدعم -std=gnu++20 (يلزم GCC 10+)؛ الحل: امسح ذاكرة npx المؤقتة أولًا، ثم CC=gcc-11 CXX=g++-11 npm install -g @deepseek-ai/dsh، ثم dsh web
فشل تشغيل dsh web بعد التثبيت العام عبر npm: وحدة node-pty الأصلية pty.node مفقودة ‏(#1219)
السبب الجذري: لا يوفّر node-pty v1.1.0 ملفًا مبنيًا مسبقًا لـ Linux x64 ‏(Node 24/ABI 137)، وسكربت تثبيت npm يفشل بصمت؛ الالتفاف اليدوي: ادخل دليل node-pty ونفّذ npx node-gyp rebuild لتوليد pty.node المفقود؛ ولا يوجد رد رسمي في المنشور (0 رد)
خطأ Ignored build scripts عند تثبيت إضافة في dsh ‏(#2230)
لم تُرصد تفاصيل الحل (تعليق واحد، دون تحقّق معمّق)؛ والظاهرة مرتبطة بسياسة pnpm الأمنية التي تتجاهل سكربتات بناء الاعتماديات افتراضيًا، ويمكن مقارنتها بحل allow-scripts في #49 — وهذا الحل بانتظار الاستكمال
